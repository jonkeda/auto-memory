# Phase 7 — Parity gate (release criteria)

**Goal:** prove the .NET port is a drop-in replacement before tagging `v1.0`.

## Gate criteria (all must pass)

1. **Test parity** — every test under `src/session_recall/tests/` has an xUnit equivalent in `net/tests/AutoMemory.Tests/` and passes on Ubuntu + Windows CI.
2. **Exit-code parity** — for the matrix below, .NET and Python return identical codes:
   - `0` success
   - `1` generic error
   - `2` bad args / usage
   - `3` DB locked
   - `4` DB not found
   - `5` schema mismatch
3. **Output parity** — golden-file diff harness asserts:
   - `--json` output is byte-identical for every subcommand.
   - Text output is byte-identical except for fields explicitly whitelisted (timestamps, durations).
4. **Telemetry parity** — see Phase 5; merged JSONL file readable by a single jq pipeline.
5. **Performance** — .NET cold-start ≤ 50ms; health run ≤ 1.2× Python baseline.

## Harness

`net/tests/Parity/` runs both CLIs against the same fixture DB and diffs output:

```
fixture-db.sqlite
cases/
  list_default.txt
  list_json.txt
  files_repo_days.txt
  search_basic.txt
  show_full_json.txt
  health_json.txt
  schema_check_json.txt
```

Each case file declares: argv, expected exit code, expected stdout (or hash), expected stderr regex, telemetry tier.

The harness:
1. Runs `python -m session_recall <argv>`.
2. Runs `./session-recall <argv>`.
3. Diffs stdout. Fails if not equal (modulo whitelisted fields).

## Fixture DB

- Generated by a deterministic Python seeder script committed under `net/tests/Parity/seed.py`.
- Includes: 25 sessions across 3 repos, 200 files, 15 checkpoints, 8 sessions with summaries, intentional gaps for freshness/coverage scoring.
- DB is small (`< 5 MB`), checked into the repo or generated in CI.

## CI integration

- New job `parity` depending on both `pytest` and `dotnet test` jobs.
- Matrix: ubuntu-latest only (golden files are line-ending sensitive; Windows handled via separate text-mode whitelist).

## Acceptance

- All gate criteria above pass.
- README updated with a "Parity tested against Python {version}" badge or footnote.
- Tag `v1.0` cut from a green parity run.

## Risks

- Subtle JSON ordering differences (`dict` insertion order vs C# anonymous types) — enforce explicit field ordering in serializers.
- Locale-dependent number formatting — `InvariantGlobalization=true` set in Phase 0 mitigates.
- Newline differences (`\n` vs `\r\n`) — force `Console.Out.NewLine = "\n"` at startup.
