# Step 05 — Publish + release checklist

## Goal
Document the human steps for cutting a release; verify the CI-published artefacts; post-release sanity tests.

## Pre-release

- [ ] All M1–M4 acceptance criteria green
- [ ] `vscode-extension/CHANGELOG.md` entry added for the new version
- [ ] `vscode-extension/README.md` reflects current feature set
- [ ] `net/Version.props` bumped (`<VersionPrefix>0.x.0</VersionPrefix>`)
- [ ] Local smoke: `pwsh ./scripts/build-all.ps1` produces 3 VSIX files; install one in a clean VS Code, run dashboard end-to-end

## Cut release

```bash
git tag v0.x.0
git push origin v0.x.0
```

## Post-release verification

- [ ] CI workflow `vscode-ext.yml` succeeded (3 build-binaries, 3 package, 1 publish)
- [ ] Marketplace listing shows new version: https://marketplace.visualstudio.com/items?itemName=auto-memory.auto-memory
- [ ] Open VSX listing shows new version: https://open-vsx.org/extension/auto-memory/auto-memory
- [ ] GitHub Release page has 3 VSIX files attached + autogenerated CLI binaries
- [ ] On Windows: `code --install-extension auto-memory.auto-memory` installs the win32-x64 build, dashboard works
- [ ] On Linux: same check
- [ ] On macOS arm64: same check

## Rollback procedure (if release is broken)

1. Marketplace: `vsce unpublish auto-memory.auto-memory@0.x.0` (requires PAT)
2. Open VSX: contact registry maintainers (no self-service unpublish)
3. Delete the GitHub release + tag
4. File an issue documenting what failed; add a regression test before the next release

## Done when
- [ ] First successful end-to-end release using this workflow
- [ ] Smoke test passed on all three platforms
